✓ A strong fit

You have a problem that resists an obvious answer.

  • Several stakeholders want different things
  • Work relies on judgement, workarounds or scattered information
  • Failure has meaningful human or organisational consequences
  • You can provide access to people, workflows or de-identified examples

× Probably not a fit

You already know every screen and feature you want.

  • A fixed website or app build with no open questions
  • Work that requires production code by semester end
  • A project with no access to real users or evidence
  • A request to add a chatbot without a defined user problem

What students are learning

Requirements are decisions—not documents.

Students learn to elicit, model, negotiate and validate requirements for contemporary socio-technical systems. They must trace every recommendation to evidence and confront uncertainty, accessibility, privacy, safety and responsible AI.

Partners receive thoughtful analysis and fresh perspectives. The educational focus is discovery and specification; implementation or production deployment is outside the scope of this subject.

Common questions
Do we need an AI project?+

No. Bring an important problem. Students will evaluate AI alongside conventional software and non-technical alternatives.

Can students sign an NDA?+

Projects should preferably use non-confidential or de-identified information. Any confidentiality needs must be discussed before the project is accepted.

Will we receive working software?+

No production system is promised. Teams may create low-fidelity prototypes to test requirements, but the primary outcome is a validated requirements package.

Who can become a partner?+

Companies, government teams, research groups, not-for-profits and community organisations are all welcome to propose a challenge.
